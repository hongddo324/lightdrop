# LightDrop: 화면 → 카메라 오프라인 파일 전송

인터넷도 케이블도 없이 **한 기기의 화면**에 컬러 애니메이션 코드를 띄우고 **다른 기기의 카메라**로 찍어서 파일을 옮깁니다.
`lightdrop.html` 파일 하나만 있으면 됩니다. 외부 라이브러리나 서버는 필요 없습니다.

## QR보다 빠른 이유

| | QR (버전 40, L) | LightDrop (96×96, 8색) |
|---|---|---|
| 칸당 비트 | 1 (흑/백) | 3 (R·G·B 채널마다 1비트) |
| 프레임당 실제 데이터 | 최대 약 2.9KB(실사용은 훨씬 작음) | 약 2.5KB(오류정정 포함 후), 128격자면 약 4.7KB |
| 놓친 프레임 | 해당 조각이 다시 나올 때까지 기다림 | **분수 코드(fountain code)**: 아무 프레임이나 K개 남짓 받으면 복원 |
| 손상된 프레임 | 버림 | 리드-솔로몬으로 코드워드당 16바이트까지 복구 |

핵심 설계는 다음과 같습니다.
1. **컬러 3채널 = 3배 밀도.** 각 칸을 R, G, B 채널마다 켜고 끕니다. 받는 쪽은 채널별로 주변 7×7칸 평균을 기준값으로 써서, 화면 밝기 얼룩이나 비네팅, 색 번짐이 있어도 판별합니다(데이터를 의사난수로 화이트닝해서 주변 평균이 늘 중간값이 되게 함).
2. **시스템 분수 코드.** 1차로 원본 블록을 순서대로 보내고, 그다음부터는 "무작위 절반 XOR" 블록과 LT(로버스트 솔리톤) 블록을 번갈아 보냅니다. 받는 쪽은 필링 디코딩과 GF(2) 가우스 소거로 빠진 블록을 채웁니다. 몇 번째 프레임을 놓쳤는지는 상관없습니다.
3. **프레임 내부 오류정정.** RS(255,223)을 여러 개 바이트 단위로 인터리빙하고, 헤더는 별도의 RS로 보호합니다.
4. **찢긴 프레임 차단.** 카메라가 화면 갱신 도중에 찍으면 위쪽은 N번 프레임, 아래쪽은 N+1번 프레임이 섞입니다. 블록 CRC에 세션과 순번을 묶어 두어서 이런 프레임은 반드시 걸러집니다.
5. **위치 찾기.** 검은 테두리를 연결요소로 찾고 → 네 모서리 → 원근 변환(호모그래피) → 테두리 경계에 맞춰 모서리를 미세조정 → 8가지 방향(회전·반전) × 5가지 격자 크기를 헤더로 자동 판별합니다.

## 사용법

1. 두 기기 모두 `lightdrop.html`을 엽니다(Chrome / Edge 권장).
2. **보내는 쪽**: [보내기] → 파일 선택 → [전송 화면 띄우기]. 전체화면 코드가 깜빡입니다.
3. **받는 쪽**: [받기] → [카메라 시작] → 코드 전체와 **흰 여백까지** 화면에 들어오게 맞추고 손을 고정합니다.
4. 진행률이 100%가 되면 무결성(CRC32)을 확인한 뒤 [파일 저장] 버튼이 나옵니다.

전송 화면 단축키: `↑/↓` 속도, `Space` 일시정지, `R` 처음부터, `Esc` 종료.

### 잘 안 될 때
- 테두리가 빨강(헤더 실패)으로 나오면 → 격자를 줄이거나(96→80) 색상 모드를 4색/흑백으로 바꾸세요.
- "프레임 손상"이 대부분이면 → 초당 프레임을 낮추세요(8→6). 화면 반사와 모아레도 확인하세요.
- 화면 밝기는 최대로, 카메라는 화면에서 30~50cm, 코드가 카메라 화면의 60~80%를 채우게.

### 휴대폰에서 여는 법
카메라는 "보안 컨텍스트"(https:// 또는 PC의 file://)에서만 켜집니다. PC에서는 파일을 더블클릭하면 됩니다. 휴대폰은 다음 중 하나를 쓰세요.
- **(권장)** 인터넷이 되는 곳에서 이 폴더(`lightdrop.html`, `sw.js`, `manifest.webmanifest`)를 GitHub Pages 같은 HTTPS 정적 호스팅에 올리고, 휴대폰으로 한 번 열어 "홈 화면에 추가"합니다. 서비스 워커가 캐시해 두므로 이후에는 **인터넷 없이** 동작합니다. 받는 쪽은 `…/lightdrop.html#rx`로 열면 바로 카메라가 켜집니다.
- 휴대폰이 **보내는 쪽**이라면 카메라가 필요 없으니 아무 방법으로 HTML을 열어도 됩니다.

## 성능 (시뮬레이션 기준, 실기기 측정 아님)
`test/sim.js`는 원근 왜곡, 회전, 블러, 색 번짐, 비네팅, 노이즈를 넣고 프레임 15% 누락, 20% 찢김 상태로 수신기를 돌립니다. 모든 조합에서 원본과 바이트 단위로 일치했습니다.
- 96×96 8색, 8fps: 프레임당 2.5KB → **약 10~14KB/s** (1MB 사진 약 1.5분, 10MB 영상 약 15분)
- 128×128 8색, 10fps: 프레임당 4.7KB → 카메라가 좋으면 약 30KB/s
- 분수 코드 효율: 30% 손실 시 블록 수의 약 1.07~1.1배만 받으면 복원(`test/fountain.js`)

`test/make_y4m.js`로 만든 가짜 카메라 영상(4:2:0 색차 서브샘플링 포함)을 headless Edge에 넣어, 실제 페이지 UI로 수신하고 무결성 검증을 통과하는 것까지 확인했습니다.

## 솔직한 한계
- 수십 MB 영상은 여전히 오래 걸립니다. 같은 공간의 두 기기라면 **USB 케이블, 블루투스, 휴대폰 핫스팟(인터넷 없이도 기기끼리 LAN 통신은 됨)**이 훨씬 빠릅니다. LightDrop은 이런 방법을 쓸 수 없을 때(케이블 없음, 페어링 불가, 망 분리 PC 등)를 위한 것입니다.
- 비슷한 접근의 선행 연구/오픈소스로 libcimbar(컬러 아이콘 매트릭스 + 분수 코드)가 있습니다. 이 구현은 그 계열 아이디어를 의존성 없는 단일 HTML로 다시 만든 것입니다.

## 테스트 실행
```
node test/fountain.js                 # 분수 코드 효율
node test/sim.js 96 3 300 6           # 격자 비트/칸 파일KB 셀픽셀
node test/make_y4m.js out.y4m 80 3 20 # 브라우저 가짜 카메라용 영상
```
